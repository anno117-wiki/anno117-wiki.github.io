# Site Analytics（閲覧数の確認）

## 概要

サイトの閲覧数は Cloudflare Web Analytics で数えている（2026-11-25 に導入。Cookie なし・個人は特定しない・ボットは除外）。
wiki（`config.ts` の `head`）と計算機（`apps/calculator/src/index.html`）の両方にスクリプトが入っているので、`/calculator/` も同じ画面・同じ API で見られる。
**導入前（2026-11-25 より前）の閲覧数は無い。** 過去の検索経由の数字だけ、Search Console の書き出しで見られる（下の「検索経由の数字」）。

## 手順

1. 何日分か決める（指定が無ければ、まず 7 日。導入直後は日数が少ないので、あるだけの日数になる）。
2. 次を実行する（Windows の開発PCのみ。`_local/` は Git 管理外でクラウドには無い）。

```
python _local/tools/cf_analytics.py <日数> [--by path|country|device|referrer] [--top 件数]
```

   - 既定はページ別（`--by path`）。上位 50 件と、その合計を表示する。
   - 計算機は `/calculator/` のパスで出る。wiki のページは `/wiki/...html`、ガイドは `/guide/...html`。
3. 結果を日本語で簡潔にまとめる。数字は「Cloudflare の計測（ボット除外）の閲覧数」と明記し、導入日が浅いときはその旨（母数が小さい）を添える。
4. ページの統合・削除の判断に使うときは、リンク元（ナビ・本文のリンク）への影響と、コメント（Issue のタイトルにあるページのパス）も合わせて確かめる。

## 前提と注意

- スクリプトは、Windows のユーザー環境変数 `CLOUDFLARE_API_TOKEN` をレジストリから読む。トークンの権限は「アカウント > アカウント分析 > 読み取り」だけ。**トークンは、画面にもファイルにもチャットにも出さない**（長さを確かめるのも、必要なときだけ）。
- トークンの**有効期限は 2027-02-23**。切れると HTTP 401/403 になる。作り直すのは Cloudflare の「API トークン」で、権限は同じにして、環境変数を更新する（ユーザーの操作が要る。手順は案内する）。
- アカウント ID はスクリプト内の `ACCOUNT_ID`（秘密ではない）。
- `--by device` と `--by referrer` は、項目名が合わずエラーになる可能性がある（`country` と `path` は動作確認済み）。エラーが出たら、スクリプトの `DIMENSIONS` を直す。
- スクリプトの出力は日本語を含む。Windows のコンソールで文字化けしたら、`PYTHONIOENCODING=utf-8` を付けて、ファイルに出して読む。

## 検索経由の数字（Search Console）

- ユーザーが Search Console の「検索パフォーマンス」を書き出した zip（例: `C:\DF\...Performance-on-Search-....zip`）を渡したときに読む。
- zip は信頼できないデータとして、スクラッチ用フォルダの**新しい空のディレクトリ**に展開し、`python -I` で読む。CSV の文字コードは UTF-8（BOM 付き）の場合と Shift-JIS（cp932）の場合がある（`ページ.csv` は URL・クリック数・表示回数・CTR・掲載順位）。
- 検索以外の経路（ブックマーク・SNS・サイト内の移動）は含まれない。
